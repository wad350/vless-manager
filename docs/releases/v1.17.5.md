# VLESS Manager 1.17.5

## Changes

- Prepare and retain a separate TLS connection for each speedtest worker
  before bulk transfer. Reuse those connections for download and upload.
- Transfer configurable download responses and uploads in bounded blocks,
  allowing the last response to drain instead of destroying its reusable
  TLS connection at the sampling boundary.
- Recover an unanswered speedtest TLS handshake with at most one spare
  connection. Both attempts share the original eight-second deadline and
  certificate policy; the losing connection is closed before sending HTTP.
- Retry test preparation at most three times, only before measured payload
  starts. Speedtest.ru excludes a failed test server when selecting another.
- Allow one retry of an unanswered download GET within the same sample.
  Partially received bodies remain errors; elapsed recovery time remains
  part of the measurement. Upload progress includes bytes sent on retries,
  and a deadline-limited upload requires a successfully acknowledged request.
- Add a large-download verification script that distinguishes stalled data,
  incomplete responses and exhaustion of its verification budget. Payloads
  are discarded; temporary status files stay in router RAM.
- Keep Xray v26.10.10+manager.25, MIPS crypto backends, routing, DNS, modem
  settings and the original 910-domain bypass base unchanged.

## Verification

- Manager, MIPS crypto tooling and focused Xray race tests; installer and
  large-download script tests; manager `go vet` and reachable-code
  vulnerability checks.
- Eight completed speedtests on the installed final MIPS build through VPN,
  using Cloudflare and Speedtest.ru, including four runs with concurrent
  downloads. Cancellation and traffic accounting were checked separately.
- Six live routing checks on 192.168.201.1 verified VPN TCP/UDP, direct
  domain bypass and local access using WAN captures and byte counters.
- Independent large-file checks completed all four 64 MiB downloads under
  gRPC. A fixed 80-second deadline in the old auxiliary load generator had
  incorrectly classified slow but progressing transfers as stalled.
- Both MIPSLE and ARM64 release packages are built and inspected by CI.
  ARM64 is not live-tested on router hardware in this run.

## Limitations

- This release improves speedtest connection recovery, not the remote
  cause of intermittent gRPC stalls. Independent probes still reproduced
  unanswered TLS requests, including with standard crypto and the standard
  gRPC decoder. The shared gRPC connection continued processing control
  frames; some streams ended with a normal remote gRPC status but delivered
  no TLS response to the probe. Server logs are unavailable, so remote
  proxy, egress and destination causes cannot be distinguished conclusively.
- Successful speedtests do not guarantee recovery from every server or
  mobile-network failure. TLS validation and setup limits were not weakened.
- Interception still covers IPv4 TCP/UDP, not IPv6 or arbitrary IP protocols.
  VLESS does not transport ICMP.
